## Workflow

1. Identify what information is needed and from whom
2. Select appropriate elicitation technique(s)
3. Prepare materials (questions, agenda, templates)
4. Execute elicitation sessions
5. Document and confirm findings
6. Identify gaps and plan follow-up sessions

## Elicitation Technique Selection

Choose technique based on context:

| Technique | Best For | When to Use |
|-----------|----------|-------------|
| **Interview** | Deep understanding of one perspective | Key stakeholders, complex domains, sensitive topics |
| **Workshop** | Group consensus, brainstorming | Cross-functional requirements, process design |
| **Survey** | Broad data collection | Large user groups, validation of findings |
| **Document Analysis** | Existing system understanding | Legacy systems, regulatory requirements |
| **Observation** | Real workflow understanding | Workflow optimization, UX improvement |
| **Prototyping** | UI/UX validation | New systems, user-facing features |
| **Interface Analysis** | System integration points | Integration projects, API design |
| **Brainstorming** | Creative solutions | Innovation projects, early ideation |

**Selection criteria to ask the user:**
- How many people need to provide input?
- How complex is the domain?
- Is there an existing system to analyze?
- How sensitive is the information?
- What is the time constraint?

## Interview Guide

### Preparation Checklist
- Define interview objective (what decisions will this inform?)
- Identify interviewee role and relevance
- Prepare 8-12 open-ended questions (30-60 min session)
- Share agenda with interviewee 2-3 days in advance

### Question Framework

Structure interview questions in this order:

**1. Context & Background (5 min)**
- "Walk me through your role and how it relates to [process/system]."
- "How long have you been doing this?"

**2. Current State (10-15 min)**
- "Describe the current process step by step."
- "What tools/systems do you use today?"
- "What data do you work with?"
- "Who do you interact with during this process?"

**3. Pain Points & Opportunities (10-15 min)**
- "What are the biggest challenges you face?"
- "Where do you spend the most time?"
- "What workarounds have you developed?"
- "If you could change one thing, what would it be?"

**4. Future State & Expectations (5-10 min)**
- "What would an ideal solution look like?"
- "What would success look like for you?"
- "Are there any constraints we should be aware of?"

**5. Wrap-up (5 min)**
- "Is there anything I haven't asked that you think is important?"
- "Who else should I talk to?"
- "Can I follow up if I have additional questions?"

### Post-Interview
- Send summary within 24 hours for confirmation
- Log action items and open questions
- Update stakeholder register if new stakeholders identified

## Workshop Facilitation

### Workshop Planning Template

| Element | Detail |
|---------|--------|
| **Objective** | [Specific outcome expected] |
| **Participants** | [Names and roles, 5-8 ideal] |
| **Duration** | [2-4 hours typical] |
| **Agenda** | [Timed activities] |
| **Materials** | [Whiteboard, sticky notes, templates] |
| **Pre-work** | [What participants should review beforehand] |

### Workshop Agenda Template (3-hour session)

1. **Opening (15 min)**: Objective, ground rules, introductions
2. **Context Setting (20 min)**: Present current state, data, constraints
3. **Activity 1 (45 min)**: Brainstorm / map current process
4. **Break (10 min)**
5. **Activity 2 (45 min)**: Prioritize / design future state
6. **Activity 3 (30 min)**: Identify gaps, risks, dependencies
7. **Wrap-up (15 min)**: Summarize decisions, assign action items, next steps

### Facilitation Techniques
- **Dot voting**: Quick prioritization (give each person 3-5 dots)
- **Affinity mapping**: Group related ideas into themes
- **MoSCoW**: Prioritize requirements (Must/Should/Could/Won't)
- **Five Whys**: Root cause analysis for pain points
- **User story mapping**: Organize features by user journey

## Survey/Questionnaire Design

### Design Principles
- Keep under 15 questions (5-8 ideal for high response rate)
- Mix question types: Likert scale, multiple choice, 1-2 open-ended
- Start with easy questions, end with open-ended
- Test with 2-3 people before distributing

### Template Structure
1. **Demographics** (1-2 questions): Role, department, experience level
2. **Current State** (3-4 questions): Usage frequency, satisfaction, tools used
3. **Pain Points** (2-3 questions): Biggest challenges, time-consuming tasks
4. **Priorities** (2-3 questions): Feature ranking, importance ratings
5. **Open Feedback** (1 question): "Anything else you'd like to share?"

## Document Analysis

### Documents to Request
- Existing SOPs / process documentation
- System manuals / user guides
- Previous project documentation
- Regulatory / compliance documents
- Organizational charts
- Sample reports / forms / screens
- Error logs / incident reports
- Training materials

### Analysis Checklist
- [ ] Identify business rules embedded in documents
- [ ] Extract data elements and definitions
- [ ] Map roles and responsibilities mentioned
- [ ] Note regulatory constraints
- [ ] Flag outdated or conflicting information
- [ ] List assumptions that need validation

## Observation Checklist

- [ ] Define what process/task to observe
- [ ] Get permission from participants
- [ ] Note: steps performed, time per step, tools used
- [ ] Note: workarounds, exceptions, pain points
- [ ] Note: handoffs between people/systems
- [ ] Note: data entered, transformed, or referenced
- [ ] Debrief with participant after observation

## Elicitation Output

After each elicitation session, produce:

1. **Session Notes**: Date, participants, key findings, decisions made
2. **Requirements Captured**: List of requirements identified (functional + non-functional)
3. **Open Questions**: Items needing follow-up
4. **Assumptions Log**: Assumptions made, to be validated
5. **Action Items**: Who, what, by when
